Hãy tưởng tượng bạn đang nhắn tin: gõ "xin ch" thì điện thoại gợi ý "ào". File bigram_lm.py chính là một "bộ não tí hon" học đúng trò đó — nhưng ở mức chữ cái thay vì từ ngữ.

👶 Ví dụ — Đứa trẻ học đánh vần: Đưa cho một đứa trẻ đọc hàng nghìn trang sách. Nó không hiểu nghĩa, nhưng nó đếm: sau chữ "q" gần như luôn là "u"; sau "t" hay là "h", "r", "o"... Rồi khi bạn đưa nó một chữ, nó đoán chữ tiếp theo dựa trên "trí nhớ đếm" đó. Bigram chính là như vậy — trí nhớ về các cặp chữ cái (bi = 2).

Cả chương trình gói gọn trong 7 bước, và toàn bộ "trí thông minh" của model chỉ là một bảng điểm hình vuông: hàng = chữ hiện tại, cột = chữ tiếp theo. Ô nào điểm cao nghĩa là "cặp này hay đi với nhau".

📥 Đầu vào

Một file văn bản corpus.txt — càng nhiều chữ càng tốt.

🧠 Bộ não

Một bảng điểm vuông V×V (V = số ký tự khác nhau). Ban đầu toàn số ngẫu nhiên.

🏋️ Học

Đọc văn bản thật, tự chấm điểm đúng/sai, rồi sửa bảng điểm — lặp tối đa 5000 lần, có "dừng sớm" nếu không tiến bộ.

✍️ Sáng tạo

Sau khi học xong: cho một chữ, tung "xúc xắc có gian lận" để viết tiếp thành đoạn văn.

🧩Từ điển khái niệm (đọc trước, hiểu sau)

8 từ khóa xuất hiện khắp file. Nắm được chừng này là đọc code như đọc truyện.

🔢 Token

Mỗi ký tự được đổi thành một con số. Ví dụ: 'a' → 5, 'b' → 6. Máy tính chỉ làm việc với số.

📚 Vocabulary (từ vựng)

Danh sách tất cả ký tự khác nhau trong văn bản, xếp theo thứ tự. Có bao nhiêu ký tự thì bảng điểm to bấy nhiêu (V×V).

🔄 Encode / Decode

Encode: dịch chữ → số để máy học. Decode: dịch số → chữ để người đọc. Như mã Morse hai chiều.

👯 Bigram

Cặp 2 chữ liên tiếp: ("h"→"e"), ("e"→"l")... Model này chỉ nhớ quan hệ cặp đôi, không nhớ xa hơn.

📉 Loss (điểm phạt)

Thước đo "đoán sai cỡ nào". Đoán sai mà còn tự tin thì bị phạt nặng. Mục tiêu: phạt càng ít càng tốt.

📦 Batch

Học theo "lớp" 32 ví dụ một lúc thay vì từng chữ một — nhanh hơn và ổn định hơn.

🌡️ Temperature

Núm vặn "độ liều" khi sáng tạo: vặn thấp → viết an toàn, khuôn mẫu; vặn cao → viết táo bạo, ngẫu hứng.

🧪 Train / Val

Train: sách giáo khoa để học (90%). Val: đề thi thử chưa từng thấy (10%) — kiểm tra có "học vẹt" không.

1Bước 1 — Chuẩn bị dữ liệu: biến chữ thành số

Máy tính không hiểu chữ "a", nó chỉ hiểu số. Nên việc đầu tiên là lập "danh bạ ký tự": liệt kê mọi ký tự khác nhau trong văn bản, xếp theo thứ tự, đánh số từ 0. Đoạn này nằm trong main() và đọc file từ tham số dòng lệnh:

# đọc file văn bản do người dùng chỉ định: python bigram_lm.py corpus.txt
text = args.input.read_text(encoding="utf-8")
chars = sorted(set(text))          # từ vựng: mọi ký tự khác nhau
stoi = {ch: i for i, ch in enumerate(chars)}  # chữ -> số (encode)
data = torch.tensor([stoi[ch] for ch in text])  # cả cuốn sách thành dãy số dài
n = int(0.9 * len(data))
train_data, val_data = data[:n], data[n:]  # cắt 90% học / 10% thi thử
📦 Mới trong bản này — import an toàn: đầu file chỉ khai báo train_data = None, val_data = None… rồi main() mới gán giá trị thật. Nhờ vậy, ai import bigram_lm từ file khác sẽ không bị "chạy ké" cả chương trình (bản cũ đọc corpus.txt ngay khi import).

Minh hoạ: mỗi ký tự được thay bằng "số báo danh" của nó trong danh bạ.

🎯 Ý tưởng then chốt: Sau bước này, cả cuốn sách chỉ còn là một dãy số dài. Mọi bước sau đó — học, đoán, sáng tạo — đều diễn ra trên dãy số này. Chỉ đến cuối cùng mới dịch ngược thành chữ cho người đọc.

2Bước 2 — Lấy batch: chuẩn bị "đề bài + đáp án"

Hàm get_batch bốc ngẫu nhiên 32 đoạn văn, mỗi đoạn dài 32 chữ (mặc định). Mỗi đoạn được cắt thành 2 bản:

  • x — đề bài: 32 chữ đầu, đưa cho model đoán.
  • y — đáp án: cũng 32 chữ đó nhưng dịch phải 1 vị trí: chữ đáp án của vị trí i chính là chữ thật đứng ngay sau nó trong văn bản.
def get_batch(split):
    split_data = train_data if split == "train" else val_data
    starts = torch.randint(len(split_data) - block_size, (batch_size,))  # 32 vị trí ngẫu nhiên
    # "Đánh chỉ số hàng loạt": một phép toán duy nhất cắt ra cả 32 đoạn cùng lúc,
    # nhanh hơn nhiều so với cắt từng đoạn bằng vòng lặp Python.
    offsets = torch.arange(block_size)          # [0, 1, 2, ..., 31]
    x = split_data[starts[:, None] + offsets]      # đề bài
    y = split_data[starts[:, None] + offsets + 1]  # đáp án = x dịch phải 1
    return x.to(device), y.to(device)

Mẹo hay của học máy: không cần ai ra đề — đáp án nằm sẵn trong văn bản, chỉ cần "dịch phải 1 ô".

3Bước 3 — Mô hình: toàn bộ trí khôn nằm trong một bảng điểm

Đây là phần "não" — class BigramLM. Nhưng đừng tưởng tượng gì cao siêu: nó chỉ là một bảng số hình vuông, kích thước V×V (V = số ký tự khác nhau).

class BigramLM(nn.Module):
    def __init__(self, vocab_size):
        # bảng điểm: hàng = chữ hiện tại, cột = chữ tiếp theo
        self.token_embedding_table = nn.Embedding(vocab_size, vocab_size)

    def forward(self, idx, targets=None):
        logits = self.token_embedding_table(idx)  # tra bảng: mỗi chữ → 1 hàng điểm
        loss = None
        if targets is not None:
            loss = F.cross_entropy(logits, targets)  # chấm điểm đúng/sai
        return logits, loss
"e" = 3.8 cao nhất → sau "b", model tin "e" là đáp án đúng nhất Ban đầu mọi ô là số ngẫu nhiên → học xong, các ô "cặp đôi hay đi với nhau" sẽ có điểm cao

Minh hoạ với 6 ký tự; thực tế bảng có kích thước V×V (ví dụ 65×65).

🧠 Hiểu "forward" trong 1 câu: Đưa một chữ vào → model lật đúng hàng đó trong bảng → trả ra cả hàng điểm số (gọi là logits) cho mọi chữ có thể đứng tiếp theo. Xong. Không có phép màu nào khác — vì đây là bigram, model không thèm nhìn các chữ trước đó.

Còn "loss" là gì? Sau khi model đưa ra hàng điểm, ta so với đáp án thật (y) bằng hàm cross_entropy. Hãy nghĩ nó như giáo viên chấm bài: đáp án đúng mà model chấm điểm thấp → phạt nặng; đoán trúng phóc → phạt ~0. Mục tiêu của cả quá trình học là làm con số phạt này nhỏ dần.

4Bước 4 — Huấn luyện: đoán → chấm → sửa, có "dừng sớm"

Vòng lặp huấn luyện trong main() chính là quá trình "luyện thi": mỗi vòng, model làm một đề 32 câu, bị chấm điểm, rồi tự sửa bảng điểm dựa trên lỗi sai. Bản mới còn thêm "huấn luyện viên" giám sát: nếu thi thử nhiều lần không tiến bộ thì cho nghỉ sớm.

for step in range(1, steps+1):   # tối đa 5000 vòng
    x, y = get_batch("train")   # 1. bốc đề ngẫu nhiên
    _, loss = model(x, y)          # 2. đoán + chấm điểm
    optimizer.zero_grad()
    loss.backward()               # 3. truy tìm: ô nào trong bảng gây ra lỗi?
    optimizer.step()                # 4. AdamW: sửa các ô đó một chút

    if step % 200 == 0:           # 5. mỗi 200 vòng: thi thử
        val_loss = estimate_val_loss(model)
        if val_loss < best_val:     # thi tốt hơn kỷ lục?
            best_val = val_loss
            torch.save(...)         # → lưu bài làm hay nhất (best_bigram.pt)
            no_improve = 0
        else:
            no_improve += 1
            if no_improve >= 5:   # 5 lần thi không tiến bộ?
                break               # → nghỉ sớm, dùng bản tốt nhất!
train loss (điểm trên sách giáo khoa) và val loss (điểm thi thử) để xem có "học vẹt" không

Lan truyền ngược (backward) = "truy tìm thủ phạm": tính xem mỗi ô trong bảng phải sửa bao nhiêu thì lỗi giảm. AdamW là "thợ sửa" khéo tay, sửa từng chút một.

🎯 Ví dụ đời thường: như luyện thi đại học — mỗi tuần thi thử một lần. Nếu 5 tuần liền điểm không tăng thì nghỉ luôn cho đỡ tốn thời gian, và giữ lại bài thi điểm cao nhất để nộp. Đó chính là --patience (mặc định 5) và file best_bigram.pt.
✅ Vì sao cần val loss? Nếu chỉ học thuộc sách giáo khoa (train loss thấp) mà thi thử (val loss) điểm kém → model đang học vẹt, không khái quát được. Đây là cách kiểm tra trung thực nhất trong học máy.

5Bước 5 — Sinh chữ: tung "xúc xắc có gian lận"

Hàm generate viết văn bản mới từng chữ một. Điểm đặc biệt của bigram: mỗi lần chỉ nhìn đúng 1 chữ cuối cùng — cả đoạn văn trước đó bị "quên" sạch.

def generate(self, idx, max_new_tokens, temperature=1.0):
    for _ in range(max_new_tokens):      # lặp: mỗi vòng thêm 1 chữ
        # chỉ nhìn CHỮ CUỐI, tra bảng điểm, chia temperature — gọn trong 1 dòng
        logits = self(idx[:, -1:])[:, 0, :] / temperature
        probabilities = F.softmax(logits, dim=-1)  # điểm → xác suất %
        next_token = torch.multinomial(probabilities, 1)  # tung xúc xắc
        idx = torch.cat((idx, next_token), dim=1)   # dán chữ mới vào cuối
    return idx
o" Tra bảng + chia T hàng "o" ÷ T Softmax → % o→?: i 40%, n 25%… 🎲 Tung xúc xắc trúng "i"! Dán vào cuối … "xin chàoi" ↺ lặp lại: giờ chữ cuối là "i", tra hàng "i" để đoán tiếp…

Vì có "tung xúc xắc", cùng một model mỗi lần chạy sẽ viết ra một đoạn văn khác nhau — giống như gieo hạt giống ngẫu nhiên.

🎲 Vì sao không chọn luôn chữ điểm cao nhất? Nếu lúc nào cũng chọn "đáp án an toàn nhất", văn bản sẽ lặp đi lặp lại một cách nhàm chán ("the the the…"). Tung xúc xắc theo đúng tỉ lệ xác suất giúp văn bản đa dạng mà vẫn "nghe có vẻ đúng" — chữ điểm cao trúng nhiều, chữ điểm thấp thỉnh thoảng trúng.

6Bước 6 — Temperature: núm vặn "độ liều" 🌡️

Trước khi tung xúc xắc, code chia mọi điểm số cho temperature (T). Công thức:

P(chữ tiếp theo) = softmax( điểm ÷ T )
  • T nhỏ (ví dụ 0.7) → khoảng cách điểm bị phóng đại: chữ đầu bảng gần như luôn thắng → văn bản an toàn, khuôn mẫu.
  • T = 1 → giữ nguyên những gì đã học.
  • T lớn (ví dụ 1.3+) → mọi chữ cào bằng nhau: chữ hiếm cũng có cửa → văn bản táo bạo, ngẫu hứng, đôi khi kỳ quặc.

File chạy thử 3 mức 0.7, 1.0, 1.3 để so sánh cùng một model viết "tính cách" khác nhau ra sao.

💡 Điều đáng nể: dù đơn sơ, bigram đã chứa mọi ý tưởng cốt lõi của model ngôn ngữ hiện đại: token hoá → dự đoán chữ tiếp theo → chấm điểm bằng cross-entropy → sửa bằng lan truyền ngược → sinh văn bản bằng sampling + temperature. ChatGPT cũng làm đúng những việc này — chỉ là ở quy mô khổng lồ và trí nhớ dài hơn.

# bigram_lm.py — Bigram Language Model (char-level), Ngày 1 buổi tối
import argparse
import math
import sys
import time
from pathlib import Path

import torch
import torch.nn as nn
import torch.nn.functional as F

torch.manual_seed(1337)
device = 'cuda' if torch.cuda.is_available() else 'cpu'

# ---------- Dữ liệu ----------
text = open('corpus.txt', encoding='utf-8').read()
chars = sorted(set(text))
vocab_size = len(chars)
stoi = {ch: i for i, ch in enumerate(chars)}
itos = {i: ch for i, ch in enumerate(chars)}
encode = lambda s: [stoi[c] for c in s]
decode = lambda l: ''.join([itos[i] for i in l])

data = torch.tensor(encode(text), dtype=torch.long)
n = int(0.9 * len(data))
train_data, val_data = data[:n], data[n:]
print(f"vocab={vocab_size}, train tokens={len(train_data)}, val tokens={len(val_data)}")

batch_size, block_size = 32, 16   # block_size = độ dài context (bigram dùng 1, nhưng giữ 16 để Bước 4)

def get_batch(split):
    # TODO (Bước 2): trả về x, y trên đúng device.
    # x: (batch_size, block_size) token đầu vào
    # y: (batch_size, block_size) token mục tiêu = x dịch phải 1 vị trí
    """Bước 2: trả về x, y có shape (batch_size, block_size)."""
    if split not in ("train", "val"):
        raise ValueError("split phải là 'train' hoặc 'val'.")
    data = train_data if split == "train" else val_data
    if len(data) <= block_size:
        raise ValueError(f"Tập {split} cần ít nhất {block_size + 1} token.")

    # high bị loại trừ: i lớn nhất là len(data) - block_size - 1.
    starts = torch.randint(len(data) - block_size, (batch_size,))
    x = torch.stack([data[i:i + block_size] for i in starts.tolist()])
    y = torch.stack([data[i + 1:i + block_size + 1] for i in starts.tolist()])
    return x.to(device), y.to(device)

# ---------- Mô hình ----------
class BigramLM(nn.Module):
    def __init__(self, vocab_size):
        super().__init__()
        # TODO (Bước 3): tạo bảng embedding vocab_size x vocab_size
        self.token_embedding_table = nn.Embedding(vocab_size, vocab_size)

    def forward(self, idx, targets=None):
        # TODO (Bước 3): logits = embedding(idx); nếu có targets thì tính loss
        logits = self.token_embedding_table(idx)  # (B, T, V)
        loss = None
        if targets is not None:
            if targets.shape != idx.shape:
                raise ValueError("targets phải có cùng shape với idx.")
            # Cross entropy nhận logits thô, không softmax trước.
            loss = F.cross_entropy(
                logits.reshape(-1, logits.size(-1)),
                targets.reshape(-1),
            )
        return logits, loss

    def generate(self, idx, max_new_tokens, temperature=1.0):
        # TODO (Bước 5): sinh token mới bằng sampling với temperature
        if not math.isfinite(temperature) or temperature <= 0:
            raise ValueError("temperature phải hữu hạn và > 0.")
        if max_new_tokens < 0:
            raise ValueError("max_new_tokens phải >= 0.")
        if idx.ndim != 2 or idx.size(1) == 0:
            raise ValueError("idx phải có shape (B, T), với T >= 1.")

        for _ in range(max_new_tokens):
            # Bigram chỉ phụ thuộc token cuối cùng, không cần cả lịch sử.
            logits, _ = self(idx[:, -1:])
            logits = logits[:, -1, :] / temperature  # (B, V)
            probabilities = F.softmax(logits, dim=-1)
            next_token = torch.multinomial(probabilities, num_samples=1)
            idx = torch.cat((idx, next_token), dim=1)
        return idx

@torch.no_grad()
def estimate_val_loss(model, eval_iters=20):
    """Đánh giá trung bình nhiều batch, không tính gradient."""
    if eval_iters <= 0:
        raise ValueError("eval_iters phải > 0.")
    was_training = model.training
    model.eval()
    try:
        losses = []
        for _ in range(eval_iters):
            x, y = get_batch("val")
            _, loss = model(x, y)
            losses.append(loss.item())
        return sum(losses) / len(losses)
    finally:
        model.train(was_training)


def peak_ram_mib():
    """Peak RAM của tiến trình, tính bằng MiB, do hệ điều hành ghi nhận."""
    if sys.platform == "win32":
        import psutil
        return psutil.Process().memory_info().peak_wset / (1024 ** 2)
    import resource
    peak = resource.getrusage(resource.RUSAGE_SELF).ru_maxrss
    # macOS trả bytes; Linux trả KiB.
    return peak / (1024 ** 2 if sys.platform == "darwin" else 1024)


def synchronize_device():
    if device.type == "cuda":
        torch.cuda.synchronize(device)


def main():
    global batch_size, block_size, device, train_data, val_data

    parser = argparse.ArgumentParser(description=__doc__)
    parser.add_argument("input", type=Path, help="File văn bản UTF-8.")
    parser.add_argument("--steps", type=int, default=5000)
    parser.add_argument("--batch-size", type=int, default=32)
    parser.add_argument("--block-size", type=int, default=32)
    parser.add_argument("--eval-interval", type=int, default=200)
    parser.add_argument("--eval-iters", type=int, default=20)
    parser.add_argument("--device", choices=("auto", "cpu", "cuda"), default="auto")
    args = parser.parse_args()
    for name in ("steps", "batch_size", "block_size", "eval_interval", "eval_iters"):
        if getattr(args, name) <= 0:
            parser.error(f"--{name.replace('_', '-')} phải > 0.")

    torch.manual_seed(1337)
    batch_size, block_size = args.batch_size, args.block_size
    selected_device = args.device
    if selected_device == "auto":
        selected_device = "cuda" if torch.cuda.is_available() else "cpu"
    if selected_device == "cuda" and not torch.cuda.is_available():
        parser.error("CUDA không khả dụng; hãy dùng --device cpu.")
    device = torch.device(selected_device)

    # Phần dữ liệu bổ sung do không xuất hiện trong ảnh.
    try:
        text = args.input.read_text(encoding="utf-8")
    except (OSError, UnicodeError) as exc:
        parser.error(f"Không đọc được file UTF-8: {exc}")
    chars = sorted(set(text))
    stoi = {ch: i for i, ch in enumerate(chars)}
    vocab_size = len(chars)
    data = torch.tensor([stoi[ch] for ch in text], dtype=torch.long)
    split_index = int(0.9 * len(data))
    train_data, val_data = data[:split_index], data[split_index:]
    if min(len(train_data), len(val_data)) <= block_size:
        parser.error(
            f"Sau chia 90/10, mỗi tập cần ít nhất {block_size + 1} token. "
            "Hãy thêm văn bản hoặc giảm --block-size."
        )

    def decode(ids):
        return "".join(chars[i] for i in ids)

    model = BigramLM(vocab_size).to(device)
    optimizer = torch.optim.AdamW(model.parameters(), lr=1e-3)
    print(f"device={device}, vocab_size={vocab_size}")

    # Bước 4: huấn luyện; mỗi 200 bước in train loss và đo val loss.
    model.train()
    if device.type == "cuda":
        torch.cuda.reset_peak_memory_stats(device)
    synchronize_device()
    started_at = time.perf_counter()
    running_loss = 0.0
    window_steps = 0
    best_val = float("inf")          # <-- thêm dòng này
    patience, no_improve = 5, 0   # thêm cạnh best_val = float("inf")
    for step in range(1, args.steps + 1):
        x, y = get_batch("train")
        _, loss = model(x, y)
        optimizer.zero_grad(set_to_none=True)
        loss.backward()
        optimizer.step()
        running_loss += loss.item()
        window_steps += 1

        if step % args.eval_interval == 0 or step == args.steps:
            val_loss = estimate_val_loss(model, args.eval_iters)
            if val_loss < best_val:                          # <-- thêm từ đây
                best_val = val_loss
                torch.save(model.state_dict(), "best_bigram.pt")
                print(f"  ★ lưu checkpoint tốt nhất (val {best_val:.4f})")
                no_improve = 0  # có cải thiện -> đếm lại từ đầu
            else:
                no_improve += 1
                if no_improve >= patience:
                    print(f"Dừng sớm ở step {step} (val không cải thiện {patience} lần liên tiếp)")
                    break
            print(                                          # <-- đến đây
                f"step {step:4d}/{args.steps} | "
                f"train loss {running_loss / window_steps:.4f} | "
                f"val loss {val_loss:.4f}"
            )
            running_loss = 0.0
            window_steps = 0

    synchronize_device()
    elapsed_seconds = time.perf_counter() - started_at
    steps_done = step  # số step chạy thật (kể cả khi dừng sớm)
    model.load_state_dict(torch.load("best_bigram.pt", weights_only=True))  # <-- thêm dòng này
    training_peak_ram = peak_ram_mib()                       # <-- thêm lại
    peak_vram = (                                            # <-- thêm lại
        torch.cuda.max_memory_allocated(device) / (1024 ** 2)
        if device.type == "cuda" else None
    )

    # Bước 6: sinh 200 token mới với mỗi temperature được yêu cầu.
    model.eval()
    for temperature in (0.7, 1.0, 1.3):
        context = torch.zeros((1, 1), dtype=torch.long, device=device)
        generated = model.generate(context, 200, temperature=temperature)
        print(f"\n--- temperature={temperature} ---")
        print(decode(generated[0].tolist()))  # Gồm 1 token đầu + 200 token mới.

    # Bước 7: thống kê, chụp trước phần sinh văn bản.
    print("\n--- Green checkpoint ---")
    print(f"Thời gian vòng huấn luyện (gồm validation/log): {elapsed_seconds:.2f} s")
    print(f"Số bước optimizer: {steps_done}")
    print(f"Peak RAM tiến trình từ khởi động đến hết train: {training_peak_ram:.2f} MiB")
    if peak_vram is not None:
        print(f"Peak VRAM tensor do PyTorch cấp phát khi train: {peak_vram:.2f} MiB")


if __name__ == "__main__":
    main()
