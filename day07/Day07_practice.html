🛠️ Ngày 7 — Buổi tối: Mini-project 1 · TinyGPT từ số 0

Bài tập tổng hợp cả tuần 1 · Ngày 1→6 giờ đây ghép thành một mô hình chạy được thật.

⏱️ ~90–120 phút 🟡 Trung bình–khó 📦 1 file duy nhất: tinygpt.py

1 · Mục tiêu buổi tối

Từ linh kiện rời của tuần 1, bạn lắp ráp và huấn luyện thật một TinyGPT (~1–5M tham số):

  • M1 (Ngày 1): dữ liệu + dataloader → batch (B, T) đúng shape.
  • M2 (Ngày 2): optimizer + gradient sanity — loss phải giảm sau vài trăm bước.
  • M3 (Ngày 3): tokenizer char-level có encode/decode round-trip đúng.
  • M4 (Ngày 4): token embedding + vị trí, shape kiểm chứng được.
  • M5 (Ngày 5): self-attention với causal mask, so với torch SDPA.
  • M6 (Ngày 6): một Transformer block + LM head, ghép thành TinyGPT.
  • M7 (Ngày 7): train loop + checkpoint + sampling + model card + báo cáo năng lượng.

Quy tắc: mỗi milestone có tiêu chí đạt (accept) — đạt rồi mới sang milestone tiếp theo. Nếu kẹt quá 20 phút ở 1 milestone, đọc hint, vẫn kẹt thì paste lỗi vào chat.

2 · Bài tập code — từng bước

M0 — Khung file và config

Tạo file tinygpt.py với khung config duy nhất. Mọi siêu tham số đặt ở đây, không hardcode trong code.

# TODO: điền config tối giản, chạy được trên CPU
config = {
    "data": "input.txt",   # văn bản train, xem M1
    "block_size": 64,      # T: độ dài ngữ cảnh
    "batch_size": 32,      # B
    "n_layer": 4, "n_head": 4, "n_embd": 128,
    "lr": 3e-4, "max_iters": 2000, "eval_every": 200,
    "seed": 1337,
}
torch.manual_seed(config["seed"])  # tái lập được (Day 9 sẽ đào sâu)
✅ Accept: python tinygpt.py chạy không lỗi import, in được config.

M1 — Dữ liệu + dataloader (Ngày 1)

Lấy 1 file văn bản tiếng Việt (hoặc tiếng Anh) ~50–200KB — ví dụ copy vài bài báo công cộng, hoặc tải tiny-shakespeare nếu muốn tiếng Anh. Mục tiêu: biến văn bản thành batch số nguyên.

# TODO 1: đọc file, tách 90% train / 10% val
# TODO 2: get_batch(split) -> x (B,T), y (B,T), trong đó y là x dịch phải 1 token
# Gợi ý: x = tokens[i : i+T], y = tokens[i+1 : i+T+1]  (dự đoán token kế tiếp)
💡 Hint: random offset mỗi lần gọi → dữ liệu không bị học thuộc thứ tự. In x.shape, x[0,:10] để mắt thấy token thật.
✅ Accept: x.shape == (32, 64), y[0,:5] == x[0,1:6] (dịch phải đúng 1 vị trí).

M2 — Tokenizer char-level + round-trip (Ngày 3)

Char-level: vocab = tập ký tự xuất hiện trong dữ liệu. Đơn giản nhưng đủ cho mini-project.

# TODO 1: xây vocab: chars = sorted(set(text)); stoi = {ch:i}; itos = {i:ch}
# TODO 2: encode(s) -> list[int]; decode(ids) -> str
# TODO 3: test round-trip: decode(encode("xin chào")) == "xin chào"
💡 Hint: test trên 1 câu tiếng Việt có dấu để bắt lỗi Unicode. Ký tự lạ khi sinh (nếu có) → ánh xạ về id 0.
✅ Accept: round-trip đúng 100% trên 100 câu ngẫu nhiên lấy từ dữ liệu.

M3 — Embedding + vị trí (Ngày 4)

# TODO 1: tok_emb = nn.Embedding(vocab_size, n_embd)
# TODO 2: pos_emb = nn.Embedding(block_size, n_embd)  # học được, đủ dùng ở quy mô này
# TODO 3: h = tok_emb(x) + pos_emb(torch.arange(T))
# TODO 4 (thêm): đếm số tham số embedding = vocab_size*n_embd + block_size*n_embd
#         → báo cáo MB (param * 4 byte / 1e6)
💡 Hint: sinusoidal (Ngày 4) thay được cho pos học được — thử cả hai, xem loss có khác biệt đáng kể không. Đó chính là "thí nghiệm" đầu tiên của bạn.
✅ Accept: h.shape == (B, T, n_embd); biết tổng tham số model (in ra, ví dụ ~1.2M).

M4 — Causal self-attention (Ngày 5) ⚠️ milestone dễ sai nhất

# TODO 1: viết Head: q,k,v = Linear(n_embd, head_size)(x)
#         scores = q @ k.T / sqrt(head_size)
# TODO 2: ÁP CAUSAL MASK: scores.masked_fill(tril == 0, -inf)  ← bắt buộc
# TODO 3: attn = softmax(scores); out = attn @ v
# TODO 4: MultiHead = concat(heads) -> Linear(n_embd)
# TODO 5: so sánh với torch.nn.functional.scaled_dot_product_attention(is_causal=True)
#         → sai số phải < 1e-5
💡 Hint: mask có thể precompute 1 lần: self.register_buffer("tril", torch.tril(torch.ones(T,T))). Quên mask là lỗi "gian lận" kinh điển — xem mục Bẫy.
✅ Accept: khớp SDPA < 1e-5; tắt mask đi thì loss train "đẹp bất thường" nhưng sample ra rác (tự kiểm chứng!).

M5 — Transformer block + TinyGPT (Ngày 6)

# TODO 1: Block = x + Attn(LayerNorm(x)); x = x + MLP(LayerNorm(x))
#         MLP: Linear(n_embd, 4*n_embd) -> GELU -> Linear(4*n_embd, n_embd)
# TODO 2: TinyGPT: embedding -> n_layer Block -> LayerNorm -> Linear(vocab_size)
# TODO 3: loss = cross_entropy(logits.view(-1, V), y.view(-1))
# TODO 4: unit test: forward 1 batch, loss là số hữu hạn, backward không NaN
💡 Hint: thứ tự Pre-LN (norm trước) ổn định hơn Post-LN ở model nhỏ. Residual x + ... đừng quên — không có nó, sâu 4 layer là gradient "chết".
✅ Accept: forward+backward 1 batch không NaN; tổng tham số in ra (mục tiêu 1–5M).

3 · Tự kiểm tra nhanh (không chấm điểm)

Câu 1. Bạn quên causal mask ở M4. Train loss giảm rất nhanh và đẹp. Tại sao đây là dấu hiệu xấu chứ không phải tốt?

Vì model được "nhìn trộm" đáp án: token ở vị trí t thấy được token t+1 (chính là thứ cần dự đoán) qua attention. Loss thấp là gian lận, không phải học. Khi sinh văn bản thật (lúc đó không có tương lai để nhìn), model hoàn toàn không biết làm gì → ra rác. Đây là lý do M4 bắt bạn tự kiểm chứng: tắt mask → loss đẹp nhưng sample rác.

Câu 2. Val loss bắt đầu tăng trong khi train loss vẫn giảm. Theo Ngày 10 sắp tới, đây là hiện tượng gì và 2 cách xử lý đầu tiên nên thử là gì?

Overfitting: model học thuộc train set, mất khả năng tổng quát. Hai cách đầu tiên: (1) tăng weight decay / giảm model size (ở quy mô này, giảm n_embd hoặc n_layer); (2) thêm dữ liệu hoặc tăng dropout (ví dụ dropout=0.1 trong attention/MLP). Dừng sớm (early stopping) dựa trên val loss cũng là đáp án đúng.

Câu 3. Green checkpoint: bạn có 2 lựa chọn — model 1M params train 2000 iters, hoặc model 4M params train 500 iters (tổng compute tương đương). Không chạy thử, bạn dự đoán lựa chọn nào cho loss tốt hơn, và vì sao câu hỏi này quan trọng với "tiết kiệm năng lượng"?

Không có đáp án chắc chắn nếu không chạy — đó chính là ý nghĩa của scaling law (Ngày 11): quan hệ giữa params, data và compute quyết định loss, không phải cứ "to là tốt". Câu hỏi quan trọng vì mỗi lựa chọn tốn cùng ngân sách năng lượng nhưng cho kết quả khác nhau; kỹ sư giỏi là người dự báo trước khi đốt điện, và luôn báo cáo loss/kWh chứ không chỉ loss.

4 · Bẫy thường gặp

🪤 Bẫy 1 — Shape đúng nhưng logic sai ở y.
y = x (quên dịch phải 1) → model học "copy token hiện tại", loss giảm ảo. Kiểm tra: y[0,:5] phải bằng x[0,1:6], không phải x[0,:5]. Mắt thường không thấy, unit test thấy ngay.
🪤 Bẫy 2 — Quên optimizer.zero_grad().
Gradient cộng dồn qua các batch → vài trăm iter đầu loss giảm, sau đó vọt lên NaN. Triệu chứng đặc trưng: loss "đẹp lúc đầu, nổ lúc sau". Fix: zero_grad() trước mỗi backward().
🪤 Bẫy 3 — Sample lúc train khác lúc sinh.
Quên model.eval() khi generate (nếu có dropout) → mỗi lần sinh cùng prompt ra kết quả khác nhau một cách bất thường, khó đánh giá. Và ngược lại: quên model.train() khi train tiếp → dropout tắt, số liệu eval/train lẫn lộn.
