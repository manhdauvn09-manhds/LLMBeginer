Phần A — Dựng "chuột bạch" đo đạc

Dùng model nhỏ + dữ liệu tổng hợp (synthetic) để lab không phụ thuộc download hay dataset thật. Nếu máy bạn có GPU thì tốt, không có vẫn chạy được trên CPU (số sẽ thấp hơn — điều đó bình thường).

import time, math, torch, torch.nn as nn
from torch.utils.data import Dataset, DataLoader

DEVICE = "cuda" if torch.cuda.is_available() else "cpu"
print("device:", DEVICE, "| torch:", torch.__version__)

# Model nhỏ kiểu decoder-only để attention có cái mà đo
class TinyBlock(nn.Module):
    def __init__(self, d=256, heads=4):
        super().__init__()
        self.attn = nn.MultiheadAttention(d, heads, batch_first=True)
        self.ln1, self.ln2 = nn.LayerNorm(d), nn.LayerNorm(d)
        self.mlp = nn.Sequential(nn.Linear(d, 4*d), nn.GELU(), nn.Linear(4*d, d))
    def forward(self, x):
        a, _ = self.attn(x, x, x, need_weights=False)
        x = self.ln1(x + a)
        return self.ln2(x + self.mlp(x))

class TinyGPT(nn.Module):
    def __init__(self, vocab=1000, d=256, layers=4):
        super().__init__()
        self.emb = nn.Embedding(vocab, d)
        self.blocks = nn.ModuleList([TinyBlock(d) for _ in range(layers)])
        self.head = nn.Linear(d, vocab)
    def forward(self, x):
        h = self.emb(x)
        for b in self.blocks: h = b(h)
        return self.head(h)

# Dữ liệu tổng hợp: không cần download, vẫn đo được bottleneck pipeline
class SynthDS(Dataset):
    def __init__(self, n=2000, seq=128, vocab=1000):
        self.x = torch.randint(0, vocab, (n, seq))
    def __len__(self): return len(self.x)
    def __getitem__(self, i): return self.x[i]

Phần B — Hàm bench(): thước đo chuẩn

Đây là phần quan trọng nhất của cả buổi tối. Đo sai ở đây thì mọi kết luận sau đều sai.

def bench(model, loader, steps=100, warmup=10):
    model.train()
    opt = torch.optim.AdamW(model.parameters(), lr=3e-4)
    it = iter(loader)
    # 1) Warmup: bỏ qua — kernel/CUDA/compile cần "nóng máy"
    for _ in range(warmup):
        x = next(it).to(DEVICE)
        opt.zero_grad(); loss = model(x).pow(2).mean()
        loss.backward(); opt.step()
    # 2) Reset bộ đếm VRAM rồi mới đo thật
    if DEVICE == "cuda":
        torch.cuda.reset_peak_memory_stats()
        torch.cuda.synchronize()
    t0 = time.time()
    for _ in range(steps):
        x = next(it).to(DEVICE)
        opt.zero_grad(); loss = model(x).pow(2).mean()
        loss.backward(); opt.step()
    # TODO (bạn làm): thêm torch.cuda.synchronize() NGAY TRƯỚC khi bấm giờ dừng,
    # rồi tính wall = time.time() - t0. Vì sao phải synchronize? (xem câu hỏi 1 bên dưới)
    tokens = steps * loader.batch_size * 128  # batch * seq_len
    tps = tokens / wall
    peak = torch.cuda.max_memory_allocated()/1e9 if DEVICE=="cuda" else 0
    return {"tokens/s": round(tps,1), "peak_GB": round(peak,2), "wall_s": round(wall,1)}

loader = DataLoader(SynthDS(), batch_size=32, shuffle=True)
model = TinyGPT().to(DEVICE)
base = bench(model, loader)
print("BASELINE:", base)

Phần D — Nhìn vào trace: kernel nào ăn thời gian nhất?

from torch.profiler import profile, ProfilerActivity
model = TinyGPT().to(DEVICE); opt = torch.optim.AdamW(model.parameters())
xb = next(iter(loader)).to(DEVICE)
acts = [ProfilerActivity.CPU]
if DEVICE == "cuda": acts.append(ProfilerActivity.CUDA)
with profile(activities=acts, record_shapes=True) as prof:
    for _ in range(20):
        opt.zero_grad(); loss = model(xb).pow(2).mean()
        loss.backward(); opt.step()
print(prof.key_averages().table(sort_by="self_cuda_time_total" if DEVICE=="cuda" else "self_cpu_time_total", row_limit=12))

2 · Tự kiểm tra nhanh (không chấm điểm — tự check hiểu bài)

Câu 1 — Bạn quên torch.cuda.synchronize() trước khi dừng bấm giờ. Con số tokens/s sẽ ra sao?

Cao một cách giả tạo. CUDA chạy bất đồng bộ: lệnh loss.backward() chỉ xếp hàng kernel lên GPU rồi trả về ngay, GPU vẫn đang cày ở đằng sau. Không synchronize mà bấm giờ dừng = bạn đo thời gian "xếp hàng", không phải thời gian "làm xong". Kết quả: tokens/s ảo cao, và mọi so sánh before/after đều vô nghĩa. Quy tắc: synchronize → bấm giờ bắt đầu … chạy … → synchronize → bấm giờ dừng.

Câu 2 — Baseline: GPU util chỉ 20%, nhưng thời gian chờ data (data time) gấp 3 lần compute time. Đây là bottleneck loại gì? Sửa bằng gì?

Bottleneck I/O — data stalls ("bếp chờ nguyên liệu" như ví dụ sáng nay). GPU rảnh 80% thời gian vì phải chờ CPU chuẩn bị batch. Sửa theo thứ tự rẻ → đắt: pin_memory=True (chuyển host→device nhanh hơn), num_workers=4 (nạp data song song), persistent_workers=True (không khởi động lại worker mỗi epoch). Đo lại: nếu tokens/s tăng mà GPU util cũng tăng → đúng bệnh, đúng thuốc.

Câu 3 — torch.compile lần chạy đầu chậm chạp, các lần sau nhanh vọt. Có nên tính lần đầu vào số đo tokens/s không?

Không. Lần đầu là chi phí biên dịch graph (one-time cost), không phải tốc độ chạy thật. Đó chính là lý do hàm bench() có warmup=10 bước bị bỏ qua. Nguyên tắc chung: loại mọi chi phí một lần (compile, warmup kernel, cache đầu tiên) ra khỏi số đo, nếu không bạn sẽ "phạt" oan đúng cái cải tiến tốt nhất.

3 · Bẫy thường gặp

🪤 Bẫy 1 — Đo mà không warmup. Vài bước đầu luôn chậm bất thường (CUDA khởi tạo, kernel chưa warm, compile lần đầu). Lấy trung bình cả 100 bước gồm cả warmup sẽ kéo số xuống và làm méo so sánh. Fix: luôn có warmup riêng rồi mới bấm giờ — như bench() mẫu.

🪤 Bẫy 2 — Đổi nhiều thứ cùng lúc rồi kết luận. Bật đồng thời pin_memory + compile + SDPA, thấy nhanh hơn → không biết cái nào thực sự có tác dụng, cái nào chỉ "ăn theo". Fix: ablation — đổi 1 biến mỗi lần, giữ seed/batch/steps giống hệt baseline. Khoa học = loại trừ, không phải cầu may.

🪤 Bẫy 3 — Đọc nhầm chỉ số bộ nhớ. torch.cuda.memory_allocated() là đang dùng lúc này; torch.cuda.max_memory_allocated() mới là đỉnh — con số quyết định OOM. Và OOM do fragmentation (bộ nhớ vỡ vụn, empty_cache cứu được) khác OOM do thực sự hết VRAM (phải giảm batch/model). Nhầm hai cái này sẽ "chữa" sai bệnh.
