def dedup(lines):
    seen, out = set(), []
    for ln in lines:
        if ln not in seen:
            seen.add(ln); out.append(ln)
    return out

Phần C — Model + vòng train có health check (Ngày 7 + Ngày 10)

Model nhỏ kiểu decoder-only, có sẵn các guard đúng chuẩn — đây là ví dụ "copy-guard" làm mẫu: khi bạn viết model của riêng mình sau này, hãy mang nguyên bộ guard này theo.

class TinyBlock(nn.Module):
    def __init__(self, d, heads):
        super().__init__()
        # Guard copy từ Ngày 7: d phải chia hết cho heads, nếu không attention vỡ shape.
        assert d % heads == 0, "d phải chia hết cho heads"
        self.attn = nn.MultiheadAttention(d, heads, batch_first=True)
        self.ln1, self.ln2 = nn.LayerNorm(d), nn.LayerNorm(d)
        self.mlp = nn.Sequential(nn.Linear(d, 4*d), nn.GELU(), nn.Linear(4*d, d))
    def forward(self, x):
        a, _ = self.attn(x, x, x, need_weights=False)
        x = self.ln1(x + a)
        return self.ln2(x + self.mlp(x))

class TinyLM(nn.Module):
    def __init__(self, vocab, d=128, heads=4, layers=2, block_size=16):
        super().__init__()
        self.block_size = block_size
        self.emb = nn.Embedding(vocab, d)
        self.pos = nn.Embedding(block_size, d)
        self.blocks = nn.ModuleList([TinyBlock(d, heads) for _ in range(layers)])
        self.head = nn.Linear(d, vocab)
    def forward(self, idx):
        T = idx.size(1)
        # Guard copy từ Ngày 7: chuỗi dài hơn block_size là lỗi vị trí, phải chặn ngay.
        assert T <= self.block_size, "chuỗi dài hơn block_size"
        pos = torch.arange(T, device=idx.device)  # guard device: arange phải cùng device với idx
        h = self.emb(idx) + self.pos(pos)
        for b in self.blocks: h = b(h)
        return self.head(h)

2 · Tự kiểm tra nhanh (không chấm điểm — tự check hiểu bài)

Câu 1 — Bạn đổi đồng thời learning rate và batch size, thấy val loss giảm. Kết luận được gì?

Không kết luận được gì về từng biến riêng lẻ. Loss giảm có thể do learning rate, do batch size, hoặc do cả hai cộng hưởng. Cách sửa: chạy 3 lần — baseline, chỉ đổi learning rate, chỉ đổi batch size. Đắt hơn hôm nay, rẻ hơn rất nhiều về lâu dài vì kết quả nào cũng kết luận được. Đây đúng là lỗi ablation ở bài lab Ngày 13.

Câu 2 — Chạy lại code ngày mai, cùng seed 42, mà loss khác hôm nay. Liệt kê 3 nguyên nhân có thể.

Ví dụ 3 nguyên nhân (Ngày 9): (1) Chỉ seed random mà quên seed torch (hoặc ngược lại) — một nguồn ngẫu nhiên chưa bị khóa là đủ làm kết quả trôi. (2) Dữ liệu hoặc thứ tự shuffle thay đổi mà không ghi manifest/hash — chạy lại trên dữ liệu khác thì số khác là đúng, không phải lỗi seed. (3) Code thay đổi mà không commit — model của "ngày mai" đã khác model của "hôm nay". Cách phòng: seed mọi nguồn + manifest ghi hash dữ liệu + config + commit code, rồi đối chiếu manifest trước khi so sánh số.

Câu 3 — Val loss giảm 0.05 nhưng task score đứng yên, rồi bạn phát hiện 5 câu val trùng câu train. Tin con số nào?

Không tin con số nào cho tới khi dedup lại. Val trùng train là contamination (Ngày 12): val loss giảm có thể chỉ là model học thuộc lòng 5 câu đó, không phải năng lực thật. Task score đứng yên càng củng cố nghi ngờ này. Cách sửa: dedup train/val triệt để, tách lại held-out sạch, chạy lại cả 3 cấu hình trên dữ liệu sạch rồi mới so sánh. Báo cáo phải ghi rõ sự cố này — giấu run lỗi là giấu dữ liệu.
