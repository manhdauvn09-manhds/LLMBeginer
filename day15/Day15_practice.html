Lab load model thật: đọc Qwen2.5-0.5B-Instruct như đọc codebase

Sáng nay bạn học cách đọc một pretrained model. Tối nay bạn làm thật: tải model 0,5 tỉ tham số về, đọc config, soi tokenizer, ráp chat template đúng, rồi cho nó sinh văn bản bằng 2 kiểu decoding khác nhau — và tự mình thấy vì sao "dùng sai template, sai bản" thì model trả lời kém hẳn.

Chuẩn bị môi trường

Model dùng trong lab: Qwen/Qwen2.5-0.5B-Instruct — bản instruct, 0,5 tỉ tham số, nhẹ (~1 GB ở bfloat16), đúng model trong bài sáng. Bạn cần tài khoản Hugging Face? Model này mở, không cần token.

💡 Mẹo tiết kiệm thời gian: lần tải đầu tiên tốn vài phút (tải ~1 GB trọng số). Các lần chạy sau dùng cache nên nhanh hơn nhiều. Nếu mạng chậm, cứ để nó tải xong — đừng ngắt giữa chừng rồi chạy lại từ đầu.

Bài 1 — Đọc config trước khi load trọng số (15 phút)

Đúng quy tắc vàng buổi sáng: đọc config + giấy phép trước, tải trọng số sau. Bạn sẽ tự tay trích ra kiến trúc, cửa sổ ngữ cảnh và ước lượng VRAM — thay vì tin vào trí nhớ.

✏️ Bạn tự làm: chạy đoạn code sau, rồi trả lời 3 câu hỏi bên dưới bằng chính số liệu nó in ra.
from transformers import AutoConfig

MODEL = "Qwen/Qwen2.5-0.5B-Instruct"
cfg = AutoConfig.from_pretrained(MODEL)
print(cfg)
print("Kiến trúc:", cfg.architectures)
print("Số lớp:", cfg.num_hidden_layers)
print("Hidden size:", cfg.hidden_size)
print("Số head / KV head:", cfg.num_attention_heads, "/", cfg.num_key_value_heads)
print("Cửa sổ ngữ cảnh:", cfg.max_position_embeddings)
print("Dtype:", cfg.torch_dtype)

Ghi lại vào sổ tay của bạn:

  1. Model này dùng Grouped-Query Attention hay Multi-Head Attention thường? Dựa vào đâu mà kết luận?
  2. Ước lượng VRAM khi load ở bfloat16: lấy tổng số tham số (xem cfg hoặc trang model) × 2 byte ≈ bao nhiêu GB? Con số này có khớp với "nhẹ ~1 GB" trong bài sáng không?
  3. Cửa sổ ngữ cảnh 32.768 token có nghĩa là gì trong thực tế — prompt + câu trả lời cộng lại tối đa bao nhiêu token?
Đáp án tham khảo (Bài 1): (1) GQA — vì num_key_value_heads (2) nhỏ hơn num_attention_heads (14), KV cache nhẹ hơn nhiều so với MHA. (2) ~0,5 tỉ × 2 byte ≈ 1 GB (chưa tính KV cache và bộ nhớ activation khi sinh). (3) Tổng độ dài prompt + output không nên vượt 32.768 token; vượt quá thì model phải cắt bớt hoặc lỗi, tùy cách bạn cấu hình.

Bài 2 — Tokenizer: model không đọc chữ, nó đọc id (15 phút)

Load tokenizer (nhẹ, không cần tải trọng số) và soi xem câu tiếng Việt bị cắt thành bao nhiêu token, special token nào xuất hiện.

from transformers import AutoTokenizer

tok = AutoTokenizer.from_pretrained("Qwen/Qwen2.5-0.5B-Instruct")
for text in ["Thủ đô của Pháp là gì?",
             "Tôi yêu AI",
             "Giải thích transformer trong một câu."]:
    ids = tok.encode(text)
    print("TEXT:", text)
    print("  tokens:", tok.convert_ids_to_tokens(ids))
    print("  ids   :", ids, "| số token:", len(ids))

print("eos:", tok.eos_token, tok.eos_token_id)
print("pad:", tok.pad_token, tok.pad_token_id)
print("Kích thước vocab:", len(tok))
✏️ Bạn tự làm:
  1. So sánh số token của câu tiếng Việt và câu tiếng Anh có độ dài tương đương. Bạn rút ra điều gì về "chi phí token" của tiếng Việt?
  2. Thử tok.encode("Thủ đô của Pháp là gì?", add_special_tokens=True) rồi add_special_tokens=False — kết quả khác nhau ở đâu? Vì sao sự khác biệt này quan trọng khi bạn tự ráp prompt?
  3. Decode ngược: tok.decode(ids) có trả lại đúng câu gốc không? Thử với một câu có dấu câu và khoảng trắng ở đầu câu.
⚠️ Bẫy số 1: đừng dùng id của tokenizer này để suy ra tokenizer khác. Mỗi họ model có bảng vocab riêng — id 1024 ở Qwen không có nghĩa gì ở Llama. Bài sáng đã nhấn mạnh: id chỉ có nghĩa trong đúng tokenizer của nó.

Bài 3 — Chat template: ráp đúng "ngôn ngữ hội thoại" (20 phút)

Đây là phần quan trọng nhất của lab. Bạn sẽ ráp cùng một câu hỏi bằng hai cách — prompt trần và prompt qua chat template — rồi cho model sinh, xem kết quả khác nhau ra sao.

from transformers import AutoTokenizer

tok = AutoTokenizer.from_pretrained("Qwen/Qwen2.5-0.5B-Instruct")
messages = [
    {"role": "system", "content": "Bạn là trợ lý hữu ích, trả lời ngắn gọn."},
    {"role": "user", "content": "Thủ đô của Pháp là gì?"},
]

# Cách A: prompt trần (KHÔNG dùng template) — cách sai với bản instruct
raw = "Thủ đô của Pháp là gì?"
# Cách B: đúng chat template của chính model này
templated = tok.apply_chat_template(messages, tokenize=False, add_generation_prompt=True)
print("=== PROMPT TRẦN ==="); print(repr(raw))
print("=== QUA CHAT TEMPLATE ==="); print(repr(templated))

Quan sát kỹ chuỗi B: bạn phải thấy <|im_start|>, tên role (system, user, assistant), <|im_end|>, và chuỗi kết thúc bằng <|im_start|>assistant — tức là "đến lượt model nói". Nếu thiếu bất kỳ mảnh nào, đó không còn là ngôn ngữ model đã học khi SFT.

✏️ Bạn tự làm:
  1. In cả hai chuỗi ra và khoanh (ghi chú) từng special token trong chuỗi B. Mỗi token đóng vai trò gì?
  2. Thử đổi system prompt thành "Bạn là một cướp biển, trả lời bằng giọng cướp biển." rồi ráp lại bằng template — chuỗi thay đổi ở chỗ nào? Điều này cho thấy system prompt thực chất chỉ là một phần của prompt, đúng không?
  3. (Nâng cao, tùy chọn) Thử dùng template của một họ model khác cho model Qwen (ví dụ tự ráp theo kiểu Llama) — bạn đoán chất lượng sẽ ra sao trước khi chạy? Ghi dự đoán rồi mới kiểm chứng ở Bài 4.

Bài 4 — Cho model sinh: greedy vs sampling (20 phút)

Giờ mới load trọng số thật và sinh văn bản. So sánh hai kiểu decoding trên cùng một prompt đã ráp đúng template.

import torch
from transformers import AutoModelForCausalLM, AutoTokenizer

MODEL = "Qwen/Qwen2.5-0.5B-Instruct"
tok = AutoTokenizer.from_pretrained(MODEL)
model = AutoModelForCausalLM.from_pretrained(
    MODEL, torch_dtype=torch.bfloat16, device_map="auto",
)
messages = [
    {"role": "system", "content": "Bạn là trợ lý hữu ích, trả lời ngắn gọn."},
    {"role": "user", "content": "Viết một câu giới thiệu về trí tuệ nhân tạo."},
]
prompt = tok.apply_chat_template(messages, tokenize=False, add_generation_prompt=True)
inputs = tok(prompt, return_tensors="pt").to(model.device)

# Greedy: luôn chọn token xác suất cao nhất
out_greedy = model.generate(**inputs, max_new_tokens=60, do_sample=False)
print("=== GREEDY ===")
print(tok.decode(out_greedy[0][inputs["input_ids"].shape[1]:], skip_special_tokens=True))

# Sampling: temperature + top-p
out_sample = model.generate(**inputs, max_new_tokens=60, do_sample=True,
                             temperature=0.8, top_p=0.9)
print("=== SAMPLING (temp=0.8, top-p=0.9) ===")
print(tok.decode(out_sample[0][inputs["input_ids"].shape[1]:], skip_special_tokens=True))
✏️ Bạn tự làm:
  1. Chạy sampling 3 lần với cùng temperature — 3 câu trả lời có giống nhau không? Còn greedy chạy 3 lần thì sao? Vì sao?
  2. Thử temperature=1.5 một lần: câu trả lời thay đổi theo hướng nào — sáng tạo hơn hay loạn hơn? Khi nào bạn muốn temperature thấp, khi nào muốn cao?
  3. Thử lại Bài 4 nhưng với prompt trần (Bài 3, cách A) thay vì prompt qua template — câu trả lời có "lạc đề" hoặc lan man hơn không? Đây chính là lỗi tân binh bài sáng đã cảnh báo.
⚠️ Bẫy số 2 — quên eos / dừng sinh: nếu bạn tự viết vòng lặp sinh thay vì dùng generate(), nhớ dừng khi gặp eos_token_id (với Qwen ChatML là <|im_end|>). Quên bước này, model sẽ "nói mãi không ngừng" — tự bịa thêm lượt user, lượt assistant giả. generate() đã lo việc này cho bạn qua generation_config, nhưng bạn phải hiểu nó đang làm gì.
⚠️ Bẫy số 3 — dtype và device: load fp32 trên CPU với model 0,5B vẫn chạy được nhưng chậm và tốn RAM gấp đôi bf16. Trên Colab/Kaggle có GPU thì để torch_dtype=torch.bfloat16, device_map="auto". Trên CPU thuần, đổi sang torch_dtype=torch.float32 và bỏ device_map nếu gặp lỗi — và giảm max_new_tokens xuống 30 cho nhanh.

🧪 3 câu tự kiểm tra nhanh

Trả lời trong đầu trước, rồi bấm "Hiện đáp án" để đối chiếu. Không chấm điểm — chỉ tự check.

Câu 1. Vì sao không nên chat trực tiếp với base model (chỉ pretrain, chưa SFT)?

Vì base model chỉ được train để "đoán token tiếp theo" trên văn bản thô, không được dạy làm theo hướng dẫn. Hỏi nó một câu, nó có thể trả lời tiếp bằng một câu hỏi khác hoặc lan man — không phải model dỏm, mà là dùng sai công cụ. Muốn chat thì dùng bản instruct, hoặc tự SFT base model (đó là Ngày 16).

Câu 2. Bạn load Qwen2.5-0.5B-Instruct nhưng tự ráp prompt theo template của Llama. Điều gì sẽ xảy ra với chất lượng trả lời, và vì sao?

Chất lượng rơi tự do. Special token, tên role và dấu xuống dòng đều là một phần của "ngôn ngữ hội thoại" model đã học khi SFT. Dùng template lạ nghĩa là đưa model một chuỗi nó chưa từng gặp khi train — nó vẫn sinh ra chữ, nhưng kém hẳn. Quy tắc: luôn dùng apply_chat_template của đúng tokenizer đi kèm model.

Câu 3. Greedy và sampling (temperature cao) khác nhau ở điểm nào, và khi nào nên dùng mỗi loại?

Greedy luôn chọn token xác suất cao nhất nên ổn định, lặp lại được — hợp cho bài toán cần chính xác, ít sáng tạo (trả lời câu hỏi thực tế, tóm tắt). Sampling chọn ngẫu nhiên theo phân phối xác suất (temperature càng cao càng "liều") nên đa dạng, sáng tạo hơn nhưng có thể loạn — hợp cho viết văn, brainstorm. Chạy greedy 3 lần cho cùng một kết quả; sampling 3 lần cho 3 kết quả khác nhau.
