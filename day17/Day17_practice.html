Ablation LoRA: rank nào đủ, rank nào thừa?

Sáng nay bạn học lý thuyết: LoRA là giả thuyết low-rank — ΔW = B·A, B khởi tạo 0, tỉ lệ α/r giữ độ lớn ổn định. Tối nay bạn kiểm chứng giả thuyết đó bằng số liệu thật: cùng một model nhỏ, cùng một dataset, chỉ đổi rank r = 4 / 8 / 16, rồi xem chất lượng thay đổi ra sao. Nhưng trước khi chạy ablation, có một việc bắt buộc: rà lại dataset và bộ đánh giá — ablation chạy trên split lệch và prompt đánh giá trùng train sẽ cho kết luận sai, dù code LoRA đúng hoàn toàn.

⏱ ~75–90 phút🐍 Python + PyTorch + peft🖥️ Colab / Kaggle GPU (T4) — có bản rút gọn chạy CPU📦 transformers, peft, torch

Quy tắc vàng của lab tối nay — viết ra trước khi chạy

“Thứ duy nhất thay đổi là rank r. Mọi thứ khác giữ nguyên: cùng dataset, cùng split, cùng seed, cùng số epoch, cùng learning rate, cùng cách sinh (greedy).”

  • Tỉ lệ α/r giữ cố định = 2 (tức α = 2r: r = 4 → α = 8; r = 8 → α = 16; r = 16 → α = 32). Đổi r mà đồng thời đổi cả tỉ lệ α/r thì không biết cải thiện đến từ rank hay từ độ lớn ΔW.
  • Số tham số train được KHÁC NHAU giữa các rank là đúng ý đồ — đó chính là thứ bạn đang đo. (Quy tắc “2 model còn bằng nhau về số tham số” của các ablation tuần trước KHÔNG áp dụng ở đây, vì rank chính là biến độc lập; điều phải giữ bằng nhau là dataset, split, seed, decoding, epoch và learning rate.)
  • Đừng đổi learning rate theo rank để “cứu” rank thấp. Rank thấp học kém chính là kết quả cần ghi nhận, không phải lỗi cần vá trong lúc đo.

⚡ Green checkpoint: ghi lại cho mỗi rank: số tham số train được, dung lượng adapter, thời gian train, train loss và val loss cuối. Cuối lab bạn sẽ trả lời được câu hỏi thực tế nhất của LoRA: “rank cao hơn tốn thêm bao nhiêu mà được thêm bao nhiêu?”

Bài 0 — Rà dataset TRƯỚC khi ablation (bắt buộc, 15 phút)

Dùng lại dữ liệu SFT bạn đã xây ở Ngày 16 (cùng template Câu hỏi: … / Trả lời: …), hoặc viết mới ít nhất 30 mẫu trộn nhiều dạng nhiệm vụ. Mỗi mẫu cần có thêm một trường kind (loại nhiệm vụ) để kiểm tra phân tầng — ví dụ: qa (hỏi đáp), summary (tóm tắt), email (viết email), translate (dịch).

Ba lỗi dataset từng được phát hiện trước lab này — kiểm tra cả ba, đừng đoán:

  1. Split validation không phân tầng: val toàn một loại mẫu (ví dụ: toàn câu dịch) trong khi train không có loại đó → val loss đo sai nhiệm vụ.
  2. Prompt đánh giá trùng train: phần lớn prompt đánh giá là nguyên văn prompt trong train → điểm cao chỉ là học thuộc, không phải học được nhiệm vụ.
  3. Masking chưa kiểm tra từng mẫu: nhãn của phần prompt phải là −100 trên mọi mẫu, không chỉ mẫu đầu tiên.

def encode_example(item):
    """Dùng đúng hàm đã kiểm chứng ở Ngày 16: token hóa riêng prompt và đáp án,
    labels che prompt bằng -100. TODO: bạn tự viết lại, không copy mù."""
    prompt = f"Câu hỏi: {item['instruction']}\nTrả lời: "
    answer = item["output"] + tok.eos_token
    prompt_ids = tok(prompt, add_special_tokens=False)["input_ids"]
    answer_ids = tok(answer, add_special_tokens=False)["input_ids"]
    input_ids = prompt_ids + answer_ids
    labels = [-100] * len(prompt_ids) + answer_ids
    return input_ids, labels

def stratified_split(data, seed=42, val_frac=0.2):
    """TODO: bạn điền phần thân hàm.
    Gợi ý: nhóm theo kind → xáo trộn mỗi nhóm bằng random.Random(seed)
    → lấy val_frac mỗi nhóm làm val, còn lại làm train → trả về (train, val)."""
    rng = random.Random(seed)
    by_kind = {}
    for item in data:
        by_kind.setdefault(item["kind"], []).append(item)
    train, val = [], []
    for kind, items in by_kind.items():
        items = items[:]  # copy, không xáo trộn list gốc
        rng.shuffle(items)
        n_val = max(1, int(len(items) * val_frac)) if len(items) >= 5 else 0
        val.extend(items[:n_val])
        train.extend(items[n_val:])
    return train, val

Bài 1 — Gắn LoRA và đếm tham số theo rank (20 phút)

Với GPT-2, target modules thực hành ở đây là c_attn (ma trận Q/K/V gộp của attention). Bắt đầu tối thiểu như bài sáng gợi ý — chỉ gắn attention trước, đừng gắn thêm MLP vội; mở rộng target modules là một ablation khác, không gộp vào lab rank tối nay.

import torch
from transformers import AutoModelForCausalLM
from peft import LoraConfig, get_peft_model

device = "cuda" if torch.cuda.is_available() else "cpu"

def count_trainable(model):
    trainable = sum(p.numel() for p in model.parameters() if p.requires_grad)
    total = sum(p.numel() for p in model.parameters())
    return trainable, total

def build_lora_model(rank):
    """TODO: bạn điền phần thân hàm.
    Gợi ý: load GPT-2 mới tinh mỗi lần (không tái dùng model đã train rank trước),

Bài 2 — Chạy ablation r = 4 / 8 / 16 (30 phút)

Chạy pilot trước: 1 rank, 1 epoch, khoảng 50 mẫu (hoặc toàn bộ train_data nếu tập của bạn nhỏ hơn) — chỉ scale lên khi eval tăng và không báo lỗi. Sau đó chạy đủ 3 rank với cùng một vòng train:

import torch
from torch.utils.data import Dataset, DataLoader
from transformers import AutoModelForCausalLM
from peft import LoraConfig, get_peft_model

# Dùng đúng encode_example() đã PASS ở Bài 0 và collate đã viết ở Ngày 16
# (đệm batch bằng pad token, nhãn đệm bằng -100, attention_mask tách thật/giả).
class SFTDataset(Dataset):
    def __init__(self, data):
        self.items = [encode_example(d) for d in data]
    def __len__(self):
        return len(self.items)
    def __getitem__(self, i):
        ids, labels = self.items[i]
        return {"input_ids": ids, "labels": labels}

def collate(batch):
    max_len = max(len(b["input_ids"]) for b in batch)
    input_ids, labels, attn = [], [], []
    for b in batch:
        pad = max_len - len(b["input_ids"])
        input_ids.append(b["input_ids"] + [tok.pad_token_id] * pad)
        labels.append(b["labels"] + [-100] * pad)
        attn.append([1] * len(b["input_ids"]) + [0] * pad)
    return {"input_ids": torch.tensor(input_ids),
            "labels": torch.tensor(labels),
            "attention_mask": torch.tensor(attn)}

# CỐ ĐỊNH cho cả 3 rank — TODO (bạn ghi rõ vào phần nộp bài):
#   seed = 42, epoch = 2, learning rate = 1e-4, batch_size = 4,
#   decoding đánh giá: greedy, max_new_tokens = 30, cùng EVAL_PROMPTS của Bài 0.
def train_one_rank(rank, train_data, val_data, epochs=2, lr=1e-4):
    """TODO: bạn điền phần thân hàm.
    Gợi ý: build_lora_model(rank) mới tinh → train trên train_data →
    tính val loss cuối trên val_data (không train trên val) →
    sinh thử trên EVAL_PROMPTS bằng greedy → trả về dict kết quả."""
    torch.manual_seed(42)
    model = build_lora_model(rank)
    loader = DataLoader(SFTDataset(train_data), batch_size=4, shuffle=True,
                        collate_fn=collate, generator=torch.Generator().manual_seed(42))
    opt = torch.optim.AdamW((p for p in model.parameters() if p.requires_grad), lr=lr)
    model.train()
    for epoch in range(epochs):
        total_loss, steps = 0.0, 0
        for batch in loader:
            batch = {k: v.to(device) for k, v in batch.items()}
            out = model(**batch)
            out.loss.backward()
            opt.step(); opt.zero_grad()
            total_loss += out.loss.item(); steps += 1
        print(f"r={rank} epoch {epoch + 1}: train loss = {total_loss / steps:.4f}")

🔬 Mở rộng (không bắt buộc, 10 phút nếu còn sức)

Thí nghiệm ablation thứ hai — nhớ viết trước câu này: “Thứ duy nhất thay đổi là target modules (chỉ c_attn so với c_attn + c_proj), mọi thứ khác giữ nguyên: cùng rank, cùng dataset, cùng seed, cùng epoch, cùng learning rate.” Chạy thêm một bản rank tốt nhất nhưng gắn thêm c_proj, so val loss với Bài 2. Đây là ablation riêng — đừng gộp kết quả của nó vào bảng rank, kẻo không biết cải thiện đến từ rank hay từ target modules.

3 câu tự kiểm tra nhanh

1. Vì sao ma trận B khởi tạo bằng 0, còn A khởi tạo ngẫu nhiên nhỏ?

Vì ΔW = B·A. B = 0 thì ΔW = 0 ngay từ đầu, bất kể A là gì — model LoRA lúc mới bắt đầu hoạt động y hệt model gốc, không hỏng kiến thức cũ ngay bước đầu tiên. Sau đó gradient cập nhật cả A và B, ΔW dần khác 0. Khởi tạo cả hai ngẫu nhiên sẽ làm model thay đổi lung tung ngay từ đầu, mất điểm xuất phát tốt của pretrained model.

2. Vì sao ablation sẽ vô nghĩa nếu prompt đánh giá trùng với prompt trong train?

Vì điểm cao khi đó chỉ đo khả năng học thuộc, không đo khả năng làm nhiệm vụ mới. Cả ba rank đều có thể “đạt điểm cao” trên prompt đã thấy, che mất sự khác biệt thật giữa rank thấp (underfit trên nhiệm vụ mới) và rank đủ. Ablation chỉ có ý nghĩa khi bộ đánh giá đo đúng thứ bạn muốn so sánh.

3. Vừa đổi rank vừa đổi α (để tỉ lệ α/r thay đổi) và vừa đổi learning rate thì kết luận được gì?

Không kết luận được gì về rank — cải thiện (hay tệ đi) có thể đến từ độ lớn ΔW hoặc tốc độ học, không phải từ rank. Muốn nói “rank 16 tốt hơn rank 4”, phải giữ α/r, learning rate, dataset, split, seed, epoch và decoding cố định, chỉ đổi rank. Đó cũng là lý do lab này bắt α = 2r và LR = 1e-4 cho cả ba lần chạy.

Bẫy thường gặp

  • Quên đóng băng model gốc: train cả base lẫn adapter thì không còn là LoRA nữa — vừa tốn VRAM như full fine-tune, vừa làm bảng ablation vô nghĩa. Khắc phục: sau khi build model, in số tham số train được và assert chỉ tham số tên chứa “lora_” mới có requires_grad=True.
  • Nhầm α với learning rate: α chỉ đổi độ lớn của ΔW, learning rate đổi tốc độ bước đi của optimizer. Khắc phục: giữ tỉ lệ α/r = 2 cố định cả ablation, chỉnh LR riêng nếu cần — và đừng chỉnh LR giữa chừng khi đang so rank.
  • Chạy ablation trên split lệch / eval trùng train: val toàn một loại mẫu, hoặc prompt đánh giá là nguyên văn prompt train → bảng đẹp nhưng kết luận sai. Khắc phục: Bài 0 phải PASS cả ba kiểm chứng (phân tầng, eval chưa thấy, masking mọi mẫu) trước khi train rank đầu tiên.
  • Merge xong ghi đè mất adapter gốc: muốn đổi nhiệm vụ lại phải train lại từ đầu. Khắc phục: luôn giữ bản W0 gốc + file adapter riêng; merge chỉ là bản triển khai cuối, và phải test lại sau merge.

Checklist nộp bài

Paste vào chat để được nhận xét chi tiết:

  1. Bài 0: kết quả 3 kiểm chứng — bảng tỉ lệ kind train/val, số prompt đánh giá và khẳng định “đều chưa từng thấy trong train”, kết quả masking trên mọi mẫu (PASS hay lỗi gì). Nếu bạn đã sửa dataset (thêm mẫu, viết lại prompt), ghi rõ đã sửa gì.
  2. Bài 1: số tham số train được của r = 4 / 8 / 16 và đối chiếu với công thức r × (d + k) — có khớp không, vì sao lệch (gợi ý: c_attn gộp Q/K/V).
  3. Bài 2: bảng ablation đầy đủ (train loss cuối, val loss cuối, thời gian train, nhận xét đầu ra trên prompt chưa thấy) + kết luận của bạn: rank nào đủ, rank nào thừa, và bằng chứng là gì.
  4. Bài 3: đầu ra trước – sau merge có giống nhau không, dung lượng adapter (MB) so với model đầy đủ.
  5. Trả lời ngắn: với nhiệm vụ này, giả thuyết low-rank đúng ở mức rank nào — và bạn sẽ chọn rank nào nếu phải triển khai thật, vì sao (chất lượng trên chi phí, không chỉ chất lượng)?
  6. (Không bắt buộc) Kết quả ablation target modules, nếu bạn làm phần mở rộng.
