🛠️ Lab: Distill thật — mô hình nhỏ học từ mô hình lớn

Buổi sáng bạn đã học: soft target và dark knowledge, temperature T, loss distillation với hệ số T², logit distillation vs sequence-level distillation, và rủi ro khi distill từ dữ liệu tổng hợp. Tối nay bạn tự tay làm: cho một student nhỏ học từ teacher lớn, rồi đo xem distillation thực sự đổi được gì — và đổi với giá nào.

⏱ ~60–90 phút🐍 Python + PyTorch, CPU🎯 Kết quả: bảng so sánh hard-label vs distillation

🎯 Mục tiêu buổi tối

  • Tính được soft target ở nhiều temperature và giải thích bằng số vì sao T = 1 chôn vùi dark knowledge.
  • Tự viết đúng loss distillation: L = α·CE + (1−α)·T²·KL(teacherT ‖ studentT).
  • Chạy một thí nghiệm có kiểm soát: cùng dữ liệu, cùng kiến trúc student, cùng seed — thứ duy nhất thay đổi là cách train (hard-label hay distillation, rồi T và α).
  • Đo đủ 3 mặt: độ chính xác, tốc độ suy luận và kích thước — để trả lời "student này có đáng thay teacher không?" theo tinh thần Green LLM.

Chuẩn bị (5 phút)

Tạo file distill_lab.py. Chỉ cần PyTorch, không cần GPU, không cần tải mô hình lớn. Dữ liệu là bài toán phân loại 3 lớp tổng hợp, cố tình thiết kế để có dark knowledge: lớp 0 gần lớp 1, và xa lớp 2 — teacher "phân vân" giữa 0 và 1 mới là thông tin quý.

import time
import torch
import torch.nn as nn
import torch.nn.functional as F

torch.manual_seed(0)

# 3 cụm: lớp 0 tại (0,0), lớp 1 tại (1.2, 0.3), lớp 2 tại (0, 4.0)
centers = torch.tensor([[0.0, 0.0], [1.2, 0.3], [0.0, 4.0]])
n_per_class = 400
xs, ys = [], []
for c in range(3):
    xs.append(centers[c] + 0.6 * torch.randn(n_per_class, 2))
    ys.append(torch.full((n_per_class,), c))
X = torch.cat(xs); y = torch.cat(ys)
perm = torch.randperm(len(X))
X, y = X[perm], y[perm]
X_train, y_train = X[:900], y[:900]
X_test, y_test = X[900:], y[900:]
print("train:", X_train.shape, "| test:", X_test.shape)

class MLP(nn.Module):
    def __init__(self, hidden):
        super().__init__()
        self.net = nn.Sequential(
            nn.Linear(2, hidden), nn.ReLU(),
            nn.Linear(hidden, hidden), nn.ReLU(),
            nn.Linear(hidden, 3))
    def forward(self, x):
        return self.net(x)

Teacher (đã viết sẵn cho bạn, chỉ việc chạy) và student nhỏ hơn:

def train_teacher(model, epochs=150):
    opt = torch.optim.Adam(model.parameters(), lr=0.01)
    for ep in range(epochs):
        opt.zero_grad()
        loss = F.cross_entropy(model(X_train), y_train)
        loss.backward(); opt.step()
    return model

teacher = train_teacher(MLP(128))
teacher.eval()
with torch.no_grad():
    acc = (teacher(X_test).argmax(1) == y_test).float().mean().item()
print(f"teacher test acc: {acc:.3f} | params: {sum(p.numel() for p in teacher.parameters())}")

Bài 1 — Nhìn dark knowledge bằng temperature (15 phút)

Lấy logits teacher cho một mẫu thuộc lớp 0, tính softmax ở T = 1, 2, 5, 10. Đừng chỉ in số — viết 1 câu nhận xét: ở T nào thì quan hệ "0 gần 1, xa 2" lộ rõ nhất, và ở T nào thì thông tin đó bắt đầu mờ đi vì phân phối tiến về đều?

with torch.no_grad():
    logits = teacher(X_test[:5])  # 5 mẫu đầu của test
for T in [1, 2, 5, 10]:
    p = F.softmax(logits / T, dim=1)
    print(f"T={T}: {p[0].tolist()}")

Kỳ vọng: ở T = 1, lớp thắng chiếm gần hết; ở T = 2–5, xác suất lớp thứ hai nổi lên rõ — đó chính là phần mà nhãn cứng không bao giờ nói cho bạn.

Trước khi code, viết ra câu này vào đầu file (theo quy tắc thí nghiệm của khóa học):

Thứ duy nhất thay đổi là cách tính loss (hard-label hay distillation); dữ liệu, kiến trúc student, seed và số epoch giữ nguyên.

Bài 3 — Thí nghiệm có kiểm soát: hard-label vs distillation (30 phút)

Student chỉ được thấy 300 mẫu train (teacher thì đã train trên đủ 900 mẫu) — đây là tình huống distillation có ý nghĩa nhất: dữ liệu có nhãn ít, nhưng teacher thì "biết nhiều". Chạy 3 cấu hình, mọi thứ khác giữ nguyên (cùng 300 mẫu, cùng kiến trúc student 32 unit, cùng seed, cùng 100 epoch):

  • A — hard-only: chỉ CE với nhãn thật.
  • B — distill T = 4, α = 0,3: loss ở Bài 2.
  • C — tự chọn: đổi MỘT thứ duy nhất so với B (T = 2 hoặc T = 10, hoặc α = 0,7) rồi ghi lại kết quả thay đổi ra sao.
def train_student(mode, T=4.0, alpha=0.3, epochs=100, seed=0):
    torch.manual_seed(seed)
    student = MLP(32)
    opt = torch.optim.Adam(student.parameters(), lr=0.01)
    Xs, ys = X_train[:300], y_train[:300]
    with torch.no_grad():
        t_logits = teacher(Xs)
    for ep in range(epochs):
        opt.zero_grad()
        s_logits = student(Xs)
        if mode == "hard":
            loss = F.cross_entropy(s_logits, ys)
        else:
            loss = distill_loss(s_logits, t_logits, ys, T=T, alpha=alpha)
        loss.backward(); opt.step()
    student.eval()
    with torch.no_grad():
        pred = student(X_test).argmax(1)
        acc = (pred == y_test).float().mean().item()
        agree = (pred == teacher(X_test).argmax(1)).float().mean().item()
    return student, acc, agree

for name, kw in [("A hard-only", {"mode": "hard"}),
                 ("B distill T=4 a=0.3", {"mode": "distill"}),
                 ("C tu chon", {"mode": "distill", "T": 2.0})]:
    _, acc, agree = train_student(**kw)
    print(f"{name}: test acc={acc:.3f} | dong y voi teacher={agree:.3f}")

Đo thêm mặt Green LLM — student có đáng thay teacher không?

def bench(model, x, n=200):
    model.eval()
    with torch.no_grad():
        t0 = time.perf_counter()
        for _ in range(n):
            _ = model(x)
        dt = (time.perf_counter() - t0) / n
    return dt * 1000  # ms / lần chạy trên 300 mẫu test

print(f"teacher: {sum(p.numel() for p in teacher.parameters())} params, "
      f"{bench(teacher, X_test):.2f} ms/lan")
sB, _, _ = train_student(mode="distill")
print(f"student: {sum(p.numel() for p in sB.parameters())} params, "
      f"{bench(sB, X_test):.2f} ms/lan")

Điều cần học không phải "distillation luôn thắng", mà là cách đo cho ra con số thay vì tin khẩu hiệu — và nhận ra khi nào student chỉ đang sao chép teacher, kể cả chỗ teacher sai (xem "Bẫy thường gặp" số 3).

✅ Tự kiểm tra nhanh (3 câu, không chấm điểm)

1. Vì sao loss distillation phải nhân thêm T², và điều gì xảy ra nếu quên nó?

Chia logits cho T làm gradient của phần KL nhỏ đi khoảng T² lần. Không nhân lại T² thì phần học từ teacher bị phần CE với nhãn cứng lấn át — student gần như chỉ học hard-label, mất tác dụng của distillation.

2. KL(teacher ‖ student) và KL(student ‖ teacher) khác nhau ra sao? Vì sao distillation dùng chiều thứ nhất?

KL không đối xứng. KL(teacher ‖ student) phạt nặng khi student gán xác suất thấp cho điều teacher tin là đúng — ép student "bao phủ" hết những gì teacher biết. Chiều ngược lại cho phép student bỏ qua những mode của teacher mà nó không thích, nên không phù hợp để chuyển giao tri thức.

3. Teacher chỉ là API đóng (chỉ trả text, không cho logits) thì dùng loại distillation nào, và mất gì so với logit distillation?

Chỉ dùng được sequence-level distillation: lấy chuỗi teacher sinh ra làm dữ liệu train như dữ liệu thật. Mất thông tin phân vân từng token — student chỉ thấy chuỗi thắng duy nhất, nên trần chất lượng thấp hơn logit distillation.

⚠️ Bẫy thường gặp

  • Quên detach teacher: để gradient chạy ngược vào teacher thì teacher cũng bị cập nhật trong lúc train student — thí nghiệm mất kiểm soát, và tốn bộ nhớ vô ích. Luôn tính teacher logits trong torch.no_grad() hoặc .detach().
  • KL sai chiều / sai dạng đầu vào: F.kl_div cần đầu vào thứ nhất là log-prob (log_softmax của student) và thứ hai là prob (softmax của teacher). Đảo hai đầu vào, hoặc đưa cả hai đều là prob, đều cho loss sai mà code vẫn chạy "bình thường" — chỉ có kết quả là lặng lẽ tệ đi.
  • So sánh không công bằng: đổi seed, đổi số epoch hay đổi tập dữ liệu giữa student A và B thì không còn biết cải thiện (nếu có) đến từ distillation hay từ may mắn. Giữ mọi thứ bằng nhau, chỉ đổi cách tính loss — và đánh giá trên test, không phải trên train.
