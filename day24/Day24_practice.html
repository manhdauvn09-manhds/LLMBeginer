🛠️ Thực hành: Pruning — cắt tỉa chỉ có nghĩa khi chạy nhanh thật

⏱ Ước lượng: 60–90 phút · Dụng cụ: Python + PyTorch (CPU là đủ) · Kiến thức nền cần nhớ, 1 dòng: sparsity cao chưa chắc nhanh hơn — chỉ tin con số latency và năng lượng đo trên đúng phần cứng, đúng batch size triển khai.

🎯 Mục tiêu buổi tối

  • Tự tay cắt tỉa một MLP nhỏ ở 3 mức 10% / 30% / 50% và đo đường cong quality–sparsity thật bằng số của chính bạn.
  • Chứng minh bằng đo đạc: cắt một phát 50% (one-shot) tệ hơn cắt dần + retrain (iterative) như thế nào.
  • So sánh unstructured (mask từng trọng số) với structured (xóa cả neuron) — và trả lời: bản nào chạy nhanh thật, bản nào chỉ nhẹ trên giấy.

Bước 0 — Khung code có sẵn (chạy được)

Lưu file prune_lab.py, chạy python prune_lab.py để chắc khung chạy tốt trước khi làm các TODO. Các chỗ TODO sẽ báo lỗi rõ ràng nếu bạn chưa điền — đó là cố ý, để bạn tự làm phần chính.

import time, torch, torch.nn as nn
from sklearn.datasets import make_classification
from sklearn.model_selection import train_test_split

torch.manual_seed(0)
X, y = make_classification(n_samples=4000, n_features=20, n_informative=12,
                           n_redundant=4, random_state=0)
Xtr, Xte, ytr, yte = train_test_split(X, y, test_size=0.25, random_state=0)
Xtr = torch.tensor(Xtr, dtype=torch.float32); ytr = torch.tensor(ytr)
Xte = torch.tensor(Xte, dtype=torch.float32); yte = torch.tensor(yte)

class MLP(nn.Module):
    def __init__(self):
        super().__init__()
        self.fc1 = nn.Linear(20, 64); self.fc2 = nn.Linear(64, 64); self.fc3 = nn.Linear(64, 2)
    def forward(self, x):
        return self.fc3(torch.relu(self.fc2(torch.relu(self.fc1(x)))))

def train(model, epochs=15, lr=0.01):
    opt = torch.optim.Adam(model.parameters(), lr=lr)
    for _ in range(epochs):
        opt.zero_grad()
        loss = nn.CrossEntropyLoss()(model(Xtr), ytr)
        loss.backward(); opt.step()
    return model

@torch.no_grad()
def accuracy(model):
    return (model(Xte).argmax(1) == yte).float().mean().item()

@torch.no_grad()
def latency_ms(model, batch=1, reps=200):
    x = Xte[:batch]
    for _ in range(20): model(x)  # warmup
    t0 = time.perf_counter()
    for _ in range(reps): model(x)
    return (time.perf_counter() - t0) / reps * 1000

def sparsity(model):
    total = sum(p.numel() for p in model.parameters() if p.dim() > 1)
    zero = sum((p == 0).sum().item() for p in model.parameters() if p.dim() > 1)
    return zero / total

base = train(MLP())
print(f"Baseline: acc={accuracy(base):.3f} latency(batch=1)={latency_ms(base):.3f} ms")

Bước 2 — One-shot vs iterative + retrain (TODO chính)

So sánh 2 cách đều tới 50% sparsity, cùng tổng số epoch retrain (ví dụ 15 epoch):

  • One-shot: cắt một phát 50%, rồi retrain 15 epoch với LR nhỏ (0.001).
  • Iterative: cắt 10% → retrain 5 epoch → cắt lên 30% → retrain 5 epoch → cắt lên 50% → retrain 5 epoch.

Điền kết quả vào bảng, rồi kết luận: cách nào giữ accuracy cao hơn, chênh lệch bao nhiêu điểm? Đây chính là quy trình chuẩn “prune → retrain → đo, lặp lại” của bài sáng.

Bước 3 — Structured pruning: xóa cả neuron (TODO nâng cao)

Viết hàm cắt cả một neuron ẩn của fc1: tính điểm quan trọng của mỗi neuron bằng chuẩn L1 của hàng weight tương ứng, xóa 25% neuron thấp điểm nhất (đặt hàng đó về 0 và cắt cột tương ứng ở fc2 — nếu chỉ cắt một phía, mô hình vẫn giữ kích thước cũ). Sau đó xây lại mô hình nhỏ thật sự (ví dụ 64 → 48 neuron) bằng cách copy weight còn lại sang một MLP mới, rồi đo latency.

Kết quả kỳ vọng: unstructured 50% gần như không đổi latency, nhưng mô hình thu nhỏ thật sau structured pruning thì latency giảm rõ rệt — đó là điểm khác biệt giữa “sparsity trên giấy” và “tốc độ thật”.

Đo thêm cả 2 batch size: batch=1 (giống sinh token) và batch=64 (giống benchmark) — và ghi nhận xem tỉ lệ tăng tốc có giống nhau không.

✅ 3 câu tự kiểm tra nhanh

1. Vì sao mô hình 90% sparsity vẫn có thể chạy chậm như cũ?

Vì lưu ở định dạng dense thì các số 0 vẫn chiếm chỗ, và kernel dense vẫn duyệt toàn bộ ma trận. Muốn nhanh thật cần cả ba: định dạng thưa (hoặc ma trận nhỏ thật), kernel biết bỏ qua số 0, và phần cứng hỗ trợ.

2. Vì sao phải retrain sau khi cắt, thay vì đo ngay?

Vì các trọng số còn lại chưa từng “biết” đồng đội của mình đã bị xóa. Một vòng fine-tune ngắn với LR nhỏ cho chúng điều chỉnh để bù lại phần thông tin đã mất — thường chỉ còn mất chưa tới 1 điểm chất lượng nếu không cắt quá tay trong một lần.

3. Khi nào chọn structured, khi nào chọn 2:4 (N:M)?

Structured: muốn nhanh ngay trên mọi phần cứng, không cần kernel đặc biệt — chấp nhận chất lượng rơi nhanh hơn vì cắt thô. 2:4: muốn ~2x trên Tensor Core (Ampere trở lên) với sparsity cố định 50%, và có framework/kernel hỗ trợ thì mới thành tốc độ thật.

⚠️ Bẫy thường gặp

1. Cắt bias và cắt cả 2 phía không khớp. Chỉ cắt weight; khi làm structured, cắt hàng ở lớp trước mà quên cắt cột ở lớp sau thì mô hình lỗi kích thước hoặc vẫn nặng như cũ.
2. Cắt một phát quá nhiều rồi kết luận “pruning vô dụng”. Cắt sốc 80% → mô hình gãy → retrain khó cứu. Luôn cắt theo vòng nhỏ và đo sau mỗi vòng.
3. Đo latency sai điều kiện triển khai. Benchmark batch=64 không đại diện cho sinh token batch=1; đo trên GPU khác máy triển khai rồi tuyên bố “nhanh hơn” cũng không có giá trị. Đo đúng phần cứng, đúng batch size.
